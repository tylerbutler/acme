- Use ASD-STE100 Simplified Technical English when you add or change code
  comments, including documentation comments and docstrings. This rule applies
  to comment prose, not to executable code or other documents.
- Add a comment only when it explains intent, a constraint, or behavior that
  the code does not make clear. Do not describe obvious code.
- Use short, direct sentences. State one topic in each sentence. Keep
  instructions to 20 words or fewer and descriptions to 25 words or fewer.
- Use active voice and simple verb forms. Make the actor clear. Use the
  imperative form for instructions.
- Use simple words with one clear meaning. Use the same term for the same
  concept. Do not use idioms, slang, or unnecessary abbreviations.
- Keep required technical terms. Preserve identifiers, API names, commands,
  paths, URLs, units, code examples, tool directives, and required legal text.
  Do not change technical meaning to simplify the language.
- Do not rewrite unchanged comments only to apply this rule.
- Check new and changed comment prose against these rules before you finish.
  These rules are practical guidance, not a copy of the complete standard or
  proof of compliance. Do not claim full ASD-STE100 compliance without a check
  against the official standard and dictionary.
